# Appendix F: The v0 Kernel Specification {#kernel-spec}

This appendix is the **normative contract** between the book and the
implementation. Chapters 1–15 explain *why*; Chapters 16–19 explain *how to
build*; this appendix states precisely *what a conforming SCTT v0 kernel must
implement*. When the prose of any chapter and this appendix disagree, this
appendix wins for implementation purposes — file an erratum against the
chapter.

It is deliberately small. Everything here corresponds to code that either
exists in the repository today or is scheduled by the Chapter 16 phase plan:

|-------|--------------|-----------------|----------------|

## F.1 Judgment Forms {#f-judgments}

A v0 kernel implements exactly these judgments. Nothing else is primitive.

```text
Γ ctx                      Γ is a well-formed context
Γ ⊢ A type                 A is a type in context Γ
Γ ⊢ a : A                  a has type A
Γ ⊢ a ≡ b : A              definitional equality (the kernel decides this
                           only on the fragments listed in §F.6.3)
Γ ⊢ r : I                  r is an interval term (I is a PRETYPE: it is
                           not a member of any universe and does not
                           support Kan operations)
Γ ⊢ φ cof                  φ is a cofibration (face formula)
Γ, φ ⊢ a : A               a is defined on the part of Γ where φ holds
```

Contexts interleave three kinds of binding: term variables `x : A`,
interval variables `i : I`, and cofibration restrictions `φ`. The
implementation (`context.rs`) keeps these in one telescope, not three
separate lists, so substitution and weakening act uniformly.

## F.2 Core Type Formers (Phase 1) {#f-core}

The Phase-1 kernel is Martin-Löf type theory with:

- **Universes** `Type₀ : Type₁ : …` with explicit cumulativity
  (`Γ ⊢ A : Typeᵢ` and `i ≤ j` give `Γ ⊢ A : Typeⱼ`); formation rules use
  `max` of levels.
- **Π-types** with β and η.
- **Σ-types** with β (projections) and η (surjective pairing).
- **Natural numbers** with the standard eliminator.
- **Booleans** with `if`.

Equality checking is by **normalization by evaluation** (NbE): evaluate to
a semantic domain (`Value` in `nbe.rs`), quote back to β-normal η-long
form, compare syntactically. De Bruijn indices in syntax, de Bruijn levels
in values. This is not an implementation detail — the conformance tests in
§F.8 fix observable behaviour of the normalizer.

**Canonicity (normative, Phase 1):** every closed term of type `ℕ`
normalizes to a numeral; every closed `Bool` to `true` or `false`. The
kernel test suite must witness this property on a generated corpus. No
canonicity claim is made for `ℝ`, `C∞`, or path types (see Chapter 8 —
those are conjectures, not contracts).

## F.3 Path Types (Phase 2) {#f-paths}

```text
Γ ⊢ A : I → Type    Γ ⊢ a : A 0    Γ ⊢ b : A 1
―――――――――――――――――――――――――――――――――――――――――――――― (PathP-form)
Γ ⊢ PathP A a b type

Γ, i : I ⊢ p : A i
―――――――――――――――――――――――――――――――――――――――――――――― (PathP-intro)
Γ ⊢ ⟨i⟩ p : PathP A (p[0/i]) (p[1/i])
```

Application `p @ r` computes: `(⟨i⟩ p) @ r ≡ p[r/i]`, and `p @ 0`, `p @ 1`
reduce to the endpoints **even when `p` is neutral** (the boundary rule is
definitional). `Path A a b` abbreviates `PathP (λ_. A) a b`.

**Warning carried over from Chapter 3:** `Path ℝ a b` is the identity type
of the set `ℝ` — it is empty for `a ≠ b`. Smooth curves are `C∞(I, M)`
(§F.6) and are unrelated to path types. A conforming kernel must NOT add
coercions between the two.

## F.4 Interval and Cofibrations (Phase 2) {#f-interval}

The v0 kernel is **Cartesian** (ABCFHL): the interval has endpoints `0`,
`1` and variables, with **no** connections (`∧`, `∨`) or reversal in the
core syntax. (The De Morgan operations in `interval.rs` are retained as a
library for the smooth layer's convenience but are not part of the
type-checking trail; the checker may not introduce them.)

Cofibrations are generated by:

```text
φ ::= ⊥ | ⊤ | (r = 0) | (r = 1) | φ ∧ φ | φ ∨ φ
```

The kernel must decide cofibration entailment `φ ⊨ ψ` — for this fragment
it is decidable by case analysis on interval variables (the
`faces_satisfiable` check in `context.rs` is the seed of this; v0 requires
the full entailment test, not just the binary-contradiction scan).

**Partial elements and systems.** A system `[φ₁ ↦ a₁, …, φₙ ↦ aₙ]` is
well-formed when the `aᵢ` agree on overlaps: for all `i, j`, under
`φᵢ ∧ φⱼ` the kernel must check `aᵢ ≡ aⱼ`. `PartialSystem::is_total` must
implement genuine cover checking (the disjunction normalizes to `⊤`), not
syntactic comparison.

## F.5 Kan Operations (Phase 2) {#f-kan}

Two primitives, in ABCFHL style; everything else is derived:

```text
coe r→r' (i. A) a          coercion along a line of types
hcom r→r' A [φ ↦ i. u] a   homogeneous composition
```

Normative computation rules the kernel must implement:

1. `coe r→r (i. A) a ≡ a` (regularity at equal endpoints).
2. `coe` computes by case analysis on the head of `A`: through `Π`
   (contravariantly on the domain, with the substitution
   `B[coe r'→i (i.A)(a)/x]` — note the *varying* endpoint, see the
   corrected rule in §3.3), through `Σ`, through `PathP`, identity on
   universes and on types not mentioning `i`.
3. `hcom` with `φ = ⊤` returns the (unique up to the system) tube value at
   `r'`; with `φ = ⊥` it returns the cap `a` when `r = r'` and otherwise
   reduces per the type head.
4. Filling is **derived**, not primitive: `fill = hcom r→z` with a fresh
   dimension variable `z`. (`OpenBox`/`fill_box` in `kan.rs` stay as
   convenience API but must lower to `hcom`/`coe`.)
5. Composition `comp` (heterogeneous) is the standard
   `hcom` -after- `coe` composite — derived, with a test pinning its
   unfolding.

**Uniqueness is propositional.** The kernel never assumes `∃!` fillers
(Chapter 7's corrected Comp-Unique). Two fillers of the same box are
path-equal; this is a theorem to be proved *in* the theory, not a kernel
equation.

**Glue (univalence)** is required for v0 only in restricted form:
`Glue A [φ ↦ (T, e)]` with formation, intro, `unglue`, and the boundary
rule `Glue A [⊤ ↦ (T, e)] ≡ T`. The full `coe`/`hcom` equations for Glue
are the single hardest part of Phase 2; a v0 kernel MAY ship with
`coe`-through-Glue restricted to constant `φ`, provided the limitation is
reported by `--explain kan-glue`.

## F.6 The Smooth Fragment (Phase 3) {#f-smooth}

### F.6.1 Primitives

```text
ℝ : Type₀                          smooth reals (a set: its Path type is trivial)
𝔻 : Type₀                          𝔻 = Σ (ε : ℝ), ε · ε ≡ 0   (first order)
𝔻(n), 𝔻ₖ                           n-dimensional / k-th order variants (§5.1)
C∞(A, B) : Type                    smooth function type (NOT the same as A → B)
ring ops  + · - : ℝ → ℝ → ℝ        with the usual commutative-ring equations
```

The smooth reals satisfy the **Kock–Lawvere axiom**, exposed to the kernel
as a *principle of definition*, not a proposition:

```text
Γ ⊢ f : C∞(𝔻, ℝ)
――――――――――――――――――――――――――――――――――― (KL-split)
Γ ⊢ kl-split f : Σ (a b : ℝ), ∀(ε:𝔻), f ε ≡ a + b·ε
```

with the computation rules `kl-split (λε. c + d·ε) ↦ (c, d, refl)` after
normalization of the body to linear form in `ε` (nilpotency `ε² ≡ 0` is a
definitional rewrite, oriented left-to-right; it is exact — there is no
`O(ε²)` remainder).

The derivative is *defined*, not postulated:
`D f x = π₂ (kl-split (λε. f (x + ε)))`.

### F.6.2 What the smooth layer must NOT do

These are conformance requirements, each traceable to a chapter erratum
fixed in this revision:

- **No case analysis on ℝ.** There is no `if x ≥ 0` at type `ℝ` — order
  is not decidable; `abs : ℝ → ℝ` must be rejected (§4.2). The kernel
  error message must name the offending comparison.
- **No unrestricted LEM.** Classical principles enter only under the
  `♯` (codiscrete) modality or for crisp hypotheses (§13.1). The kernel
  has no `extract : 🅒 A → A`.
- **No Taylor-series equation.** `f ≡ taylor-limit f a` is not a kernel
  equation at `C∞` (smooth ≠ analytic, §4.2). Taylor's theorem with
  remainder is a library theorem, not a rewrite.
- **The scalar chain rule is** `D(f ∘ g) ≡ (D f ∘ g) · D g` — a theorem
  derived from KL-split, never a definitional equation; the functorial
  form `T(f ∘ g) ≡ T f ∘ T g` lives at tangent bundles only (§5.2).

### F.6.3 Decidable equality fragments

The kernel decides `≡` only on:

1. the cubical/MLTT core (via NbE, conditional on the normalization
   conjecture of §8.4 — implementations must terminate on the test corpus
   and may impose a fuel limit with error `e-fuel`);
2. polynomial and rational identities over ℝ (normal form: sparse
   multivariate polynomials over ℚ with nilpotent generators);
3. linear-in-ε terms after KL normalization.

Everything else (transcendental identities, smooth function equality) is
**undecidable by Richardson's theorem** (§6.4 — about the class, not any
single instance) and must be handled by the proof layer, never by the
kernel's conversion check.

## F.7 Lipschitz Types (Phase 4) {#f-lipschitz}

```text
Lip(A, B, k) : Type        functions A → B with Lipschitz constant ≤ k
```

with `k : ℚ≥0` a *static* annotation. Normative rules:

- composition multiplies constants: `Lip(A,B,k) → Lip(B,C,k') → Lip(A,C,k·k')`;
- `C∞(ℝ,ℝ)` functions with globally bounded derivative `|D f| ≤ k` embed
  into `Lip(ℝ,ℝ,k)`;
- the **certified robustness bound** uses the factor-2 radius: a classifier
  with Lipschitz constant `k` and margin `m` at input `x` is certifiably
  constant on the ball of radius `m/(2k)` (§17.2 — each logit moves by less
  than `m/2`, so a gap of `m` cannot close).

Phase 4 is intentionally thin in v0: subtyping `Lip(A,B,k) ≤ Lip(A,B,k')`
for `k ≤ k'`, no inference of constants (annotations are checked, not
synthesized).

## F.8 Conformance Test Suite {#f-tests}

A kernel claims v0 conformance by passing all of:

| ID | Property | Source |
|----|----------|--------|
| T1 | NbE soundness: `norm a ≡ a` provable for the MLTT corpus | §F.2 |
| T2 | Canonicity at ℕ/Bool on generated closed terms | §F.2 |
| T3 | Path boundary: `p @ 0`, `p @ 1` reduce on neutrals | §F.3 |
| T4 | `coe r→r ≡ id`; Π/Σ/PathP coe rules on the Ch. 16 examples | §F.5 |
| T5 | `hcom` degenerate cases (`φ = ⊤`, `φ = ⊥`) | §F.5 |
| T6 | System agreement checked on overlaps (reject mismatched tubes) | §F.4 |
| T7 | `ε² ≡ 0` rewrite confluent with ring normalization | §F.6.1 |
| T8 | `kl-split` computes `D(x²) = 2x`, `D(sin) = cos` symbolically | §F.6.1 |
| T9 | `abs : ℝ → ℝ` and `if x ≥ 0` at ℝ are REJECTED with named error | §F.6.2 |
| T10 | Chain rule derivable, not definitional (conversion check fails, tactic succeeds) | §F.6.2 |
| T11 | Lipschitz composition constants; robustness radius `m/(2k)` exact | §F.7 |
| T12 | Brunerie-lite: `π₁(S¹) ≅ ℤ` winding computation terminates | Ch. 15/16 |

T12 is the integration smoke test: it exercises HITs, univalence-lite, and
the loop-space encode/decode in one computation. The full Brunerie number
is explicitly *not* a v0 requirement (Chapter 15 records it as a stretch
benchmark).

## F.9 Versioning and Errata {#f-errata}

This specification is versioned with the book. Changes to F.1–F.8 require:
(1) an erratum entry referencing the affected chapter; (2) a migration note
for `sctt-core`; (3) updated conformance tests in the same commit. The
specification deliberately excludes everything still labeled *conjecture*
in Chapter 8 — the kernel contract only ever contains what can be tested.
